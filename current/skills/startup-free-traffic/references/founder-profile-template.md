# Founder Profile Template

The persistent context file that replaces repeated diagnosis. When creating one, fill it from the conversation in the user's language — never leave generic placeholders. When reading one, treat facts older than ~2 months as candidates for a "is this still true?" check, especially Stage and Traction.

Save as `founder-profile.md` (or `about_me.md`) in the user's project/workspace.

```markdown
# Founder Profile: [Name]
*Last updated: [date] — update after any significant change in stage, traction, or strategy.*

## Product
- **What it is:** [one sentence]
- **Ideal customer (ICP):** [specific — role, segment, geography, language]
- **B2B / B2C:** [and who pays vs. who uses, if different]
- **Do people actively search for this solution?** [yes / no / partially — this drives channel choice]
- **Natural sharing mechanic?** [yes: what / no]

## Stage & Traction
- **Stage:** [pre-launch / MVP live / post-launch]
- **Current users/customers:** [number, and how active]
- **Current traffic sources:** [what already brings people, if anything]

## Founder Resources
- **Weekly hours for growth work:** [n]
- **Natural strengths:** [writing / video / talking to people / data / design ...]
- **Comfort zones to respect:** [e.g., "won't do camera", "hates cold outreach"]

## Existing Assets
- **Audience:** [followers/list sizes per platform, or "none"]
- **Communities the ICP lives in:** [specific groups/forums]
- **Personal network relevance:** [connections that matter]
- **Content/data that could become lead magnets:** [...]

## Strategy Log
- **Chosen channels:** [1-2, with date chosen]
- **What worked:** [...]
- **What didn't (and why we think so):** [...]
- **Explicitly ruled out for now:** [channels + reason — prevents re-litigating]

## Constraints & Notes
- [budget realities, timeline pressures (e.g., fundraising deadline), language/market specifics]
```

## Usage rules

- **On read:** skip diagnostic questions already answered here; confirm anything stale.
- **On write/update:** preserve the Strategy Log history — append, don't overwrite. The log of what failed is as valuable as what worked.
- **Privacy:** this file may contain business-sensitive details; keep it in the user's own workspace, never embed it into the skill itself.
