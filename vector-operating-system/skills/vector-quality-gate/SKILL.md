# Vector Quality Gate

Before you present a significant output, check each item. If an item fails, revise before you deliver.

## Relevance
- Does it solve the user's actual problem?
- Is it at the right level of detail for the reader?

## Accuracy
- Are technical claims checked against a source or a run?
- Are commands, paths, filenames, dates and links checked?
- Is anything guessed that could have been checked?

## Tone
- Direct, practical, authentic.
- No fluff, no hype, no fake certainty.

## Platform fit
- Does the structure fit the destination (chat, email, doc, slide, PR)?
- Would a competent operator send this as it is?

## Report
If any check could not be run (no network, no access, no tool), list it under "Not verified" at the end of the output. Never present an unchecked item as checked.
